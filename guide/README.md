# xlfn User Guide

The guide is maintained as mdBook-compatible Markdown. Read
[`src/introduction.md`](src/introduction.md) on GitHub or use
[`src/SUMMARY.md`](src/SUMMARY.md) as its table of contents. Detailed
[reference documents](../docs/reference) and rustdoc hold API specifics.

## Preview and build

Run these commands from the **repository root** with mdBook installed:

```console
mdbook serve guide --open
```

To build the static site without starting a server:

```console
mdbook build guide
```

Generated files are written to `guide/book/` and should not be committed.

## Validate

The checker uses only the Python 3.11+ standard library. Check source navigation,
local paths, included files, and formatting without building the book:

```console
python3 -B guide/check.py
```

After a build, also check rendered links, fragments, assets, and chapter coverage:

```console
mdbook build guide
python3 -B guide/check.py --html
python3 -B -m unittest discover -s guide -p 'test_check.py'
```

The HTML check uses the IDs generated by mdBook, including punctuation and
repeated headings. It does not check external websites or compile Rust examples.
Run the applicable Rust, Windows artifact, and Excel checks separately.

## Maintain the guide

- Keep task steps in the guide and detailed API rules in `docs/reference/`.
- Keep task pages in the order readers perform the work, with expected results.
- Update `SUMMARY.md` when adding a chapter and keep existing filenames when possible.
- Recheck fragment links when changing headings. Use an explicit external GitHub
  URL for repository maintainer documents that are not shipped with the book.
- Update examples and reference material together when an API or CLI changes.
- Run both source and rendered checks before publishing generated HTML.
