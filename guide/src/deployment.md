# Deployment and distribution

Distribute the output directory generated by `cargo xlfn package`.

## Produce target directories

From the add-in project directory:

```powershell
# Build both 32-bit and 64-bit packages
cargo xlfn package --all --locked
```

This generates `package/win-x86/` and `package/win-x64/`. Distribute the directory
matching your users' Excel process bitness, or include both in an installer that
selects the appropriate package.

## Package contents

Each target directory contains:

- `<artifact-name>.xll`: The compiled native add-in;
- Any configured companion/sidecar files;
- `build-manifest.json`: Manifest recording build metadata and artifact names and sizes.

Keep these files together in the same directory. If your add-in depends on companion
DLLs, moving the `.xll` without its dependencies can prevent it from loading.

## Installation and loading

Distribute the package to a permanent directory on the user's machine (e.g. within
`%LOCALAPPDATA%` or a standard program files directory). Avoid loading add-ins
directly from temporary or downloads directories.

In Excel:
1. Go to **File → Options → Add-ins**.
2. Select **Excel Add-ins** under **Manage** and click **Go...**.
3. Click **Browse...** and select the `.xll` file.

## Updating an add-in

Excel locks loaded `.xll` and `.dll` files while the application is running:

1. Close all running Excel instances before replacing add-in files.
2. Replace the package files.
3. Restart Excel and verify the updated functions.

If packaging reports `distribution commit interrupted`, the output directory
may contain the previous package, the new package, or no package. The error
identifies the transaction location; the packaging API also exposes the possible
previous-package location. Keep any retained transaction and backup directories
in place, and retry the same packaging command. Its commit step recovers retained
transactions before replacing the output again.

Follow the transaction journal when recovering an interrupted update. A backup
left after a committed update is only pending cleanup; the newly installed
package remains authoritative.

## Versioning worksheet functions

When evolving your add-in:

- Prefer backward-compatible additions (such as adding optional parameters).
- For breaking changes to function names or argument layouts, consider introducing
  a new function name (e.g. `MYFUNC.V2`) so existing workbooks continue to evaluate
  consistently.
